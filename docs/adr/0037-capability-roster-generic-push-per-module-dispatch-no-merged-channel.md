# Capability roster in shared, generic snapshot push, per-module dispatch; merged push channel rejected

The 2026-08-27 architecture review found every capability's depth in its own module (right) but its edges stamped out by hand across `main.rs`, `snapshot.rs`, and a renderer pre-seed list frozen at four names while nine snapshot capabilities existed (a `shell.lua` reading `mpris:get()` at boot dropped into rescue). We decided:

1. **One generic `push_snapshot`** over `&impl Serialize` replaces the nine per-capability `push_*_snapshot` clones and the tenth inlined audio copy. ADR-0029 already keeps payloads untyped; the capability name is the only real datum.
2. **The capability roster lives in `shared`** (`shared::CAPABILITIES`). The renderer seeds one live signal per rostered name, so every rostered Lua global exists from a generation's first evaluation and reads `nil` until its first dependency snapshot arrives. That nil-until-hydrated contract is uniform, including `sysinfo`, which stays `nil` indefinitely until configured. `push_snapshot` debug-asserts roster membership so a forgotten roster entry fails on the supervisor's first push in development, not in a user's `shell.lua` at boot. The lazy signal path stays as the fallback for unrostered names.
3. **Each capability module owns its action dispatch** via one `dispatch(controller, envelope)` adapter holding its action match, argument parse, and `tokio::spawn`. `main.rs` keeps a literal match with one arm per capability: static calls, no registry, no trait. Prerequisite: `NetworkState`/`BluetoothState` ownership moved into their controllers behind `handle_signal(signal) -> State` (their state is signal-dependent, so this is their equivalent of the seven later controllers' `build_state()`; ADR-0029/0030 pin the behavior, immediate `scanning` flip and clear-on-discovery, not which module holds the field). The immediate flip and clear route through each controller's own signal channel as new variants (`ScanStarted`, `DiscoveryCleared`), so they share the real signals' FIFO ordering, and the single `pending_network_connect` slot moved into `NetworkController` with the rest of network's state.

## Rejected: merging the seven single-variant `Changed` channels into one `(capability, payload)` channel

Proposed and rejected. Once decisions 1 and 3 land, each capability's residue is one single-variant enum, one channel, and a one-line select arm; the merge would trade that inert repetition for serialize-in-controller indirection plus two permanent carve-outs (idle is event-shaped per ADR-0032, audio's mixer arm is bespoke). Do not re-propose unless a capability needs to push from a context that cannot reach the main loop's select.
